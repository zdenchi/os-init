# Open WebUI + Hermes на Orange Pi через Tailscale

Для Armbian Debian ARM64, користувача `adminpi` та вже встановленого Hermes. Open WebUI встановлюємо поруч з агентом. Інтерфейс доступний через HTTPS лише в Tailscale, без SSH-тунелю на телефоні.

## 1. Схема підключення

| Компонент | Адреса |
|---|---|
| API Hermes | `127.0.0.1:8642` |
| Open WebUI | `127.0.0.1:3000` |
| Доступ із телефона/ПК | HTTPS-адреса Tailscale Serve |

Порт 9119 dashboard Hermes не використовується цією інтеграцією. Discord і Hermes Mobile можуть працювати паралельно. Дії агента виконуються на Orange Pi з правами користувача Hermes.

Інструкція для нової інсталяції. Якщо контейнер `open-webui` вже існує, спочатку перевір `sudo docker ps -a`: не видаляй наявні дані або контейнер без з’ясування його конфігурації.

## 2. Увімкни API Hermes

Під `adminpi`:

```bash
openssl rand -hex 32
nano ~/.hermes/.env
```

Збережи згенерований ключ у менеджері паролів. Додай або зміни чинні рядки, не дублюючи їх:

```dotenv
API_SERVER_ENABLED=true
API_SERVER_HOST=127.0.0.1
API_SERVER_PORT=8642
API_SERVER_KEY=ЗАМІНИ_СВОЇМ_ЗГЕНЕРОВАНИМ_КЛЮЧЕМ
```

```bash
chmod 600 ~/.hermes/.env
hermes gateway restart
hermes gateway status
curl --fail --max-time 10 http://127.0.0.1:8642/health
```

Очікується JSON зі статусом `ok`. Якщо API вимкнений явно через параметри платформи у конфігурації, усунь цю суперечність; не запускай другий gateway вручну поряд зі службою.

Цей API — агент Hermes з його моделлю та інструментами, а не пряме підключення Open WebUI до OpenAI. Для нього використовується окремий локальний ключ `API_SERVER_KEY`.

## 3. Підготуй Docker

Якщо Docker ще не встановлений, для Armbian Debian:

```bash
sudo apt update
sudo apt install -y docker.io openssl
sudo systemctl enable --now docker
sudo docker version
```

Якщо Docker уже встановлений з офіційного репозиторію Docker, не встановлюй поверх нього пакет `docker.io`. Використовуй наявну інсталяцію. Користувача Hermes не потрібно додавати до групи `docker`.

## 4. Створи налаштування Open WebUI

```bash
mkdir -p ~/open-webui
chmod 700 ~/open-webui
openssl rand -hex 32
nano ~/open-webui/webui.env
```

Другий згенерований ключ призначений для `WEBUI_SECRET_KEY`, він має відрізнятися від ключа API Hermes.

```dotenv
HOST=127.0.0.1
PORT=3000
WEBUI_AUTH=true
WEBUI_SECRET_KEY=ЗАМІНИ_ДРУГИМ_ВИПАДКОВИМ_КЛЮЧЕМ
ENABLE_OLLAMA_API=false
OPENAI_API_BASE_URL=http://127.0.0.1:8642/v1
OPENAI_API_KEY=ВСТАВ_ТОЙ_САМИЙ_КЛЮЧ_ЩО_API_SERVER_KEY
```

```bash
chmod 600 ~/open-webui/webui.env
```

Не залишай текстові приклади ключів. `WEBUI_SECRET_KEY` надалі зберігай незмінним, зокрема під час оновлень.

## 5. Запусти Open WebUI

Перевір, що порт 3000 вільний:

```bash
sudo ss -lntp 'sport = :3000'
```

Якщо він зайнятий іншим сервісом, обери інший вільний порт у `webui.env` і використовуй його також у команді Tailscale Serve нижче.

```bash
sudo docker run -d \
  --name open-webui \
  --network host \
  --env-file "$HOME/open-webui/webui.env" \
  -v open-webui:/app/backend/data \
  --restart unless-stopped \
  ghcr.io/open-webui/open-webui:slim
```

Образ `slim` підходить для чату через API та не містить усіх локальних ML-компонентів стандартного образу. Локальне розпізнавання мовлення, embeddings та обробка документів можуть потребувати додаткових компонентів.

`--network host` використовує мережу Orange Pi, тому контейнер бачить API Hermes на `127.0.0.1`. Публікація портів `-p` тут не потрібна. Це не мережева ізоляція контейнера від хоста.

Історія, користувачі та налаштування зберігаються у volume `open-webui`. Не видаляй його під час оновлення.

Перевір:

```bash
sudo docker logs --tail 80 open-webui
sudo ss -lntp 'sport = :3000'
curl -I --max-time 10 http://127.0.0.1:3000/
```

Дочекайся завершення першого запуску. Порт має слухати `127.0.0.1:3000`, а не `0.0.0.0:3000`. Якщо він відкритий на всіх інтерфейсах, зупини контейнер і перевір, чи застосувалася змінна `HOST` у поточному образі, перш ніж продовжувати.

## 6. Увімкни приватний HTTPS через Tailscale

```bash
tailscale status
tailscale serve status
```

Якщо Serve уже обслуговує інший сервіс на HTTPS 443, не замінюй його конфігурацію навмання: обери окремий підтримуваний порт Serve або спочатку визнач, який сервіс має залишитися на 443.

Якщо конфлікту немає:

```bash
sudo tailscale serve --bg http://127.0.0.1:3000
```

Якщо команда виведе посилання для дозволу HTTPS/Serve, відкрий його на своєму ПК та підтвердь. Після цього повтори команду за потреби.

```bash
tailscale serve status
```

Скопіюй фактичну HTTPS-адресу з виводу, наприклад:

```text
https://orangepi5.назва-tailnet.ts.net
```

На телефоні або ПК увімкни Tailscale в тому самому tailnet і відкрий цю адресу в браузері. Не використовуй приклад адреси буквально.

У політиці Tailscale дозволь HTTPS/TCP 443 до Orange Pi лише потрібним пристроям або користувачу. За стандартної широкої політики інші члени tailnet також можуть бачити сторінку входу. Залиш автентифікацію Open WebUI увімкненою.

**Funnel не вмикай:** для цієї задачі доступ із публічного інтернету не потрібний. Порти 3000/8642 на Keenetic та UFW відкривати не потрібно. Serve у фоновому режимі зберігає налаштування; сервіс `tailscaled` має бути ввімкнений:

```bash
sudo systemctl enable --now tailscaled
```

## 7. Створи особистий обліковий запис

1. Відкрий HTTPS-адресу Serve.
2. Створи свій обліковий запис. Перший користувач стає адміністратором.
3. У **Admin Panel → Settings** вимкни подальшу реєстрацію користувачів. Назва перемикача залежить від версії.
4. Перевір список користувачів: для особистого використання залиш лише свій обліковий запис.

Не використовуй `WEBUI_AUTH=false`.

## 8. Перевір підключення до Hermes

У списку моделей має з’явитися `hermes-agent` або назва профілю Hermes. Якщо моделі немає:

**Аватар → Admin Panel / Admin Settings → Settings → Connections → OpenAI → Manage → Add Connection**.

| Поле | Значення |
|---|---|
| URL | `http://127.0.0.1:8642/v1` |
| API Key | Точне значення `API_SERVER_KEY` |
| API Type | `Chat Completions` |

Перевір з’єднання та збережи. У режимі host network адреса `127.0.0.1` правильна; `host.docker.internal` тут не потрібна.

Після першого запуску Open WebUI зберігає підключення у своїй базі. Для зміни URL/ключа використовуй панель адміністратора: самого редагування `webui.env` може бути недостатньо. Не видаляй volume заради виправлення ключа.

Тестовий запит:

> Відповідай українською. Покажи поточний робочий каталог на сервері, нічого не змінюй.

Перевір, що відповідь отримана саме від агента Hermes. Інструменти працюють на Orange Pi, а не на телефоні.

## 9. Використання на телефоні

Увімкни Tailscale і відкрий HTTPS-адресу в Chrome. За наявності пункту **Встановити застосунок / Додати на головний екран** можна використовувати Open WebUI як PWA.

Перевір підключення і через домашній Wi-Fi, і через мобільний інтернет. Адреса залишається однакова; приватний SSH-ключ у браузер імпортувати не потрібно.

## 10. Керування та автозапуск

Контейнер запускається після перезавантаження завдяки Docker та `--restart unless-stopped`. Якщо його зупинено вручну, запусти знову:

```bash
sudo docker start open-webui
```

Інші команди:

```bash
sudo docker restart open-webui
sudo docker stop open-webui
sudo docker logs --tail 100 open-webui
sudo docker logs -f open-webui
hermes gateway status
tailscale serve status
```

Не публікуй логи без перевірки на секрети й особисті дані.

## 11. Резервна копія перед оновленням

Збережи `~/open-webui/webui.env` окремо в захищеному місці. Він містить секрети. Дані скопіюй із зупиненого контейнера:

```bash
mkdir -p ~/open-webui/backups
chmod 700 ~/open-webui/backups
sudo docker stop open-webui
```

Скопіюй каталог даних; ця команда створює окрему директорію з часовою позначкою:

```bash
sudo docker cp open-webui:/app/backend/data "$HOME/open-webui/backups/data-$(date +%F-%H%M%S)"
sudo chmod -R go-rwx "$HOME/open-webui/backups"
sudo docker start open-webui
```

Якщо копіювання завершилось помилкою, запусти контейнер назад і з’ясуй причину перед оновленням. Копія містить чати й конфігурацію; перенеси її на інший накопичувач або довірений ПК. Резервна копія лише на тому самому SSD не захищає від його поломки.

### Оновлення

Після успішної резервної копії:

```bash
sudo docker pull ghcr.io/open-webui/open-webui:slim
sudo docker stop open-webui
sudo docker rm open-webui
```

Повтори команду `docker run` із розділу 5 з тим самим volume і файлом налаштувань. Не використовуй `docker volume rm open-webui`. Тег `slim` рухомий; для відтворюваного розгортання можна зафіксувати перевірений digest образу.

## 12. Типові проблеми

| Проблема | Перевірка |
|---|---|
| Контейнер не запускається | `sudo docker logs --tail 100 open-webui`, доступність порту 3000, місце на диску |
| Немає моделей | API Hermes, URL із `/v1`, правильний ключ у збереженому підключенні |
| Invalid API key / 401 | `OPENAI_API_KEY` у підключенні має збігатися з `API_SERVER_KEY` |
| HTTPS-адреса не відкривається | Tailscale на обох пристроях, `tailscale serve status`, політика доступу TCP 443 |
| Після зміни `.env` нічого не змінилось | Hermes потребує restart; Docker env потребує відтворення контейнера; збережені підключення Open WebUI редагуються у панелі |
| Немає локальних embeddings/STT | Образ slim не містить повного ML-стека |
| Відповідь довга | Hermes може виконувати інструменти; перевір журнал gateway й стан агента |

Локальні перевірки:

```bash
curl --max-time 10 http://127.0.0.1:8642/health
curl -I --max-time 10 http://127.0.0.1:3000/
sudo docker ps --filter name=open-webui
tailscale serve status
```

## Чекліст

- [ ] API Hermes працює на loopback і захищений ключем.
- [ ] Open WebUI працює на `127.0.0.1:3000`.
- [ ] Дані зберігаються у volume.
- [ ] Установлено окремий постійний `WEBUI_SECRET_KEY`.
- [ ] Створено особистий аккаунт, реєстрацію вимкнено.
- [ ] Модель Hermes відповідає.
- [ ] HTTPS через Tailscale працює поза домом.
- [ ] Доступ tailnet обмежений потрібними пристроями.
- [ ] Funnel, DMZ і проброси портів не вмикалися.
- [ ] Після перезавантаження інтерфейс доступний.
