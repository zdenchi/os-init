# Підготовка Orange Pi 5 до встановлення Hermes Agent

## 0. Налаштування SSH

Стандартний перший SSH-вхід для деяких штатних образів Armbian: `root`, пароль `1234`.

```bash
ssh root@<IP_ORANGE_PI>
```

Створіть адміністративного користувача під час першого запуску.

```bash
sudo adduser adminpi
sudo usermod -aG sudo adminpi
```

На своєму комп’ютері скопіюй ключ на Orange Pi.

```bash
ssh-copy-id adminpi@<IP_ORANGE_PI>
```

Додати конфіг для швидкого підключення до Orange Pi:

```bash
nano ~/.ssh/config
```

```text
Host orangepi
  HostName <IP_ORANGE_PI>
  User adminpi
  IdentityFile ~/.ssh/id_rsa
```

SSH: лише ключі, без root-підключення

```bash
sudo tee /etc/ssh/sshd_config.d/99-hardening.conf >/dev/null <<'CONF'
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
PubkeyAuthentication yes
X11Forwarding no
AllowTcpForwarding yes
CONF

sudo sshd -t
sudo systemctl reload ssh
```

## 1. Оновлення та базові пакети

```bash
sudo apt update
sudo apt full-upgrade -y
sudo apt install -y \
  ca-certificates curl wget git jq vim nano htop btop tmux \
  unzip rsync openssh-server ufw fail2ban unattended-upgrades \
  apt-listchanges smartmontools
sudo reboot
```

Після перезавантаження увійдіть знову. Перевірте автоматичні оновлення:

```bash
sudo systemctl enable --now fail2ban
sudo dpkg-reconfigure unattended-upgrades
systemctl status unattended-upgrades --no-pager
```

## 2. Tailscale для приватного віддаленого доступу

Встановлення за офіційним керівництвом (або через стабільний APT-репозиторій Tailscale):

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
sudo tailscale ip -4
```

## 3. UFW на самому Orange Pi

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
# Заміни <HOME_SUBNET> на свою домашню підмережу, наприклад 192.168.1.0/24
sudo ufw allow from <HOME_SUBNET> to any port 22 proto tcp
sudo ufw allow in on end0 from 192.168.50.1 to any port 22 proto tcp
sudo ufw allow in on tailscale0 to any port 22 proto tcp
sudo ufw enable
sudo ufw status verbose
```

**Важливо про Docker:** Docker керує власними правилами netfilter; опубліковані контейнерні порти можуть **обходити UFW**. Не публікуйте порти контейнерів (`ports:`) без потреби, захищайте зовнішню мережу на Keenetic, а детальнішу політику Docker реалізуйте через документований `DOCKER-USER` / актуальні механізми Docker firewall.

## 4. Встановлення Docker Engine і Compose (офіційний репозиторій Debian 13)

```bash
sudo apt update
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF2
Types: deb
URIs: https://download.docker.com/linux/debian
Suites: trixie
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF2

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
```

Перевірка:

```bash
sudo docker version
sudo docker compose version
sudo docker info --format '{{.Architecture}} / {{.CgroupVersion}}'
sudo docker run --rm hello-world
```

**Безпека:** не додавайте обліковий запис Hermes і звичайних користувачів без потреби до групи `docker`; вона надає практично root-доступ до хоста. Для адміністрування використовуйте `sudo docker`.

## 5. Підготовка каталогів для двох Hermes

Створіть окремі каталоги даних:

```bash
sudo install -d -m 0700 /srv/hermes/personal
sudo install -d -m 0700 /srv/hermes/work
sudo install -d -m 0700 /srv/hermes/backups
sudo ls -ld /srv/hermes/*
```

Під час встановлення контейнерів права володіння та точні шляхи монтування потрібно узгодити з UID користувача **всередині обраного офіційного образу Hermes**. Не виправляйте проблеми дозволів командою `chmod -R 777`.

Для кожного агента окремо: Telegram Bot Token, API-ключ, memory/history, робочий каталог, файлові дозволи. Не надавайте контейнерам `/var/run/docker.sock` і права `--privileged`; якщо знадобиться browser sandbox, окремо налаштуйте безпечний backend і перевірте його ізоляцію.

## 6. Ресурси для браузерної автоматизації

Для 8 ГБ RAM — стартові **планові максимуми**, а не постійно зарезервована пам’ять:

| Компонент                         |        План |
| --------------------------------- | ----------: |
| Hermes Personal + browser/sandbox |   до 2.5 ГБ |
| Hermes Work + browser/sandbox     |     до 3 ГБ |
| ОС, Docker, Tailscale             |   ~1–1.5 ГБ |
| Вільний запас                     | ~0.7–1.2 ГБ |

Якщо Playwright/Chromium працює в **окремому контейнері**, його RAM **не входить** у ліміт `mem_limit` іншого контейнера. Встановлюйте ліміти на **всю групу**: Hermes + browser, а не по 5–7 ГБ кожному процесу. Для Chromium орієнтовно `shm_size: 1g`, без `--privileged`; за потреби зменште кількість паралельних вкладок/контекстів.

Перевірка пам’яті та CPU:

```bash
free -h
nproc
cat /sys/fs/cgroup/cgroup.controllers
sudo docker stats --no-stream
```

Під час активної браузерної автоматизації стежте за температурою, OOM і throttling:

```bash
cat /sys/class/thermal/thermal_zone*/temp 2>/dev/null
journalctl -k -b | grep -Ei 'oom|out of memory|thermal|throttl' | tail -30
```

Часті записи на microSD не рекомендовані; SSD кращий. Swap/zram — страховка від сплесків, **не заміна RAM**. Не задавайте одночасно великі swap-файли і zram, не перевіривши наявну конфігурацію:

```bash
swapon --show
zramctl
```

**Після цього** переходьте до окремої інструкції обмеження доступу на роутері.
