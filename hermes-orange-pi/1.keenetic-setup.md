# Ізоляція Orange Pi 5 з Hermes Agent на Keenetic

## 1. План мережі

| Параметр                    | Значення (приклад)                                                  |
| --------------------------- | ------------------------------------------------------------------- |
| Основний сегмент            | `Home`, `192.168.1.0/24`                                            |
| Новий сегмент               | `Hermes-Isolated`, `192.168.50.0/24`                                |
| IP роутера в сегменті       | `192.168.50.1`                                                      |
| Orange Pi (резервація DHCP) | `192.168.50.10`                                                     |
| Підключення                 | Виділений LAN-порт (наприклад, порт 3, **лише якщо він вільний**)   |
| Керування Orange Pi         | SSH через Tailscale; порти з інтернету не відкривати                |

Якщо домашня мережа використовує іншу підмережу, змініть приклад. Нова підмережа не повинна перетинатися з іншими локальними мережами або VPN.

## 2. Збережіть конфігурацію роутера

1. Підключіться до Keenetic зі звичайного домашнього комп’ютера.
2. Відкрийте `http://my.keenetic.net` або адресу керування свого роутера.
3. У розділі **Керування → Параметри системи** знайдіть збереження файлу конфігурації (`startup-config`) і завантажте резервну копію.

## 3. Створіть окремий сегмент

1. Відкрийте **Мої мережі та Wi-Fi → Сегменти**.
2. Натисніть **+** і створіть сегмент із назвою `Hermes-Isolated`.
3. **Не вмикайте** «Доступ до застосунків, що працюють на Keenetic» / «Дозволити доступ до інтернет-центру» (назва залежить від версії).
4. У розділі **Налаштування IP** задайте адресу `192.168.50.1`, маску `255.255.255.0`, увімкніть DHCP-сервер.
5. У розділі **Порти та VLAN** призначте **лише один вільний LAN-порт** сегменту `Hermes-Isolated` (стан «Належить сегменту»).
6. Перевірте, що цей порт не залишився учасником основного сегмента, а інші домашні порти не були перепризначені.
7. Збережіть зміни.

## 4. Підключіть Orange Pi

1. Підключіть Ethernet Orange Pi до виділеного порту Keenetic.
2. Переконайтеся, що Orange Pi отримує адресу `192.168.50.x` (на Orange Pi: `ip -4 addr` і `ip route`).
3. У веб-інтерфейсі Keenetic знайдіть Orange Pi серед клієнтів нового сегмента і закріпіть за ним адресу `192.168.50.10` через DHCP-резервацію, якщо доступна.
4. Після резервації перепідключіть мережевий інтерфейс або перезапустіть Orange Pi і перевірте адресу.

## 5. Ізоляція між сегментами

В актуальній KeeneticOS додаткові сегменти **за замовчуванням не мають доступу до інших сегментів**. Для сценарію Hermes **не додавайте дозволяючих правил** між `Hermes-Isolated` і `Home`.

Відкрийте **Мережеві правила → Міжмережевий екран** і перевірте:

- На інтерфейсі `Hermes-Isolated` немає правил **Дозволити** до `192.168.1.0/24` та інших домашніх/VPN-підмереж.
- На основному сегменті немає широких правил, що дозволяють непередбачений доступ до `Hermes-Isolated`.
- Не використовується команда `no isolate-private`: вона знімає сегментну ізоляцію глобально.
- Доступ із нового сегмента до застосунків і керування **самого Keenetic** вимкнено (див. крок 3).

Для додаткового захисту за наявності старих нестандартних дозволяючих правил можна налаштувати явні **Заборонити** для домашньої підмережі на вхідному інтерфейсі `Hermes-Isolated`, але спочатку перевірте пріоритет правил і фактичну поведінку. Не блокуйте бездумно DNS/DHCP на адресі маршрутизатора — це може вимкнути інтернет у Orange Pi.

Якщо у вас є інші підмережі (IoT, камери, NAS, WireGuard, VPN, інші VLAN), перевірте заборону доступу і до них: обмеження лише `192.168.1.0/24` недостатньо.

Перевіряйте заборону до конкретного **свого** домашнього пристрою (адресу замініть):

```bash
nc -vz -w 3 192.168.1.10 22
```

## 6. Додати дозволяюче правило для SSH із домашньої мережі на роутері

| Поле в інтерфейсі              | Значення                                               |
| ------------------------------ | ------------------------------------------------------ |
| Увімкнути правило              | Увімкнено                                              |
| Ім’я                           | `SSH до Orange Pi`                                     |
| Інтерфейс                      | `Основний` — домашній сегмент, звідки підключається ПК |
| Дія                            | `Дозволити`                                            |
| Тип IP-адреси джерела          | `Підмережа`                                            |
| IP-адреса джерела              | `192.168.1.0`                                          |
| Маска підмережі                | `255.255.255.0 (/24)`                                  |
| Тип IP-адреси призначення      | `IP-адреса`                                            |
| IP-адреса призначення          | `192.168.50.10`                                        |
| Протокол                       | `TCP/22 - Secure Shell (SSH)`                          |
| Номер порту джерела            | `Будь-який`                                            |
| Розклад роботи                 | `Працює постійно`                                      |

У поле IP джерела вводь **`192.168.1.0` без `/24`** (або свою домашню підмережу): маска вибирається окремо. Призначення — IP Orange Pi з DHCP-резервації.

Якщо замість готового протоколу `TCP/22 - Secure Shell (SSH)` обрано звичайний `TCP`, додатково встановіть **порт призначення: «Дорівнює» → `22`**. Порт джерела залиш будь-яким.

## 7. Підсумковий чекліст

Доступ до домашніх сегментів заборонений, немає доступу до керування роутером із сегмента Hermes

```bash
sudo nmap -Pn -sT -p 22,80,139,443,445,3389 \
  192.168.1.1-254
```

Очікування: немає відповідей.

При цьому DNS має працювати:

```bash
dig @192.168.50.1 google.com +short
```
