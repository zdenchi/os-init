# Kali Linux Live USB із зашифрованим Persistence (LUKS)

Покрокова інструкція для Ubuntu/Linux. **Kali Live** запускається з USB без встановлення на комп’ютер, а файли, налаштування та встановлені програми зберігаються на окремому зашифрованому розділі.

> **Увага:** команди запису ISO знищать **усі дані флешки**. Команди `luksFormat` і `mkfs.ext4` знищать дані **третього розділу**. Перед кожною операцією звіряй пристрій за розміром і моделлю. У прикладі `/dev/sda` — флешка, але після перепідключення ім’я може змінитися. Ніколи не підставляй його наосліп.

## 1. Підготовка

Потрібні:

- USB-флешка від 16 ГБ (рекомендується 32–64 ГБ, USB 3.0).
- Комп’ютер з Ubuntu/Linux і правами `sudo`.
- [Kali Linux Live ISO](https://www.kali.org/get-kali/#kali-live) (не Installer ISO).
- Пакети `cryptsetup`, `parted` і `util-linux`.

```bash
sudo apt update
sudo apt install -y cryptsetup parted util-linux
```

За можливості перевір контрольну суму ISO за значеннями на офіційному сайті:

```bash
sha256sum ~/Downloads/kali-linux-*-live-amd64.iso
```

## 2. Визначення флешки

Підключи USB-накопичувач і виконай:

```bash
lsblk -o NAME,SIZE,MODEL,TRAN,FSTYPE,MOUNTPOINTS
```

Знайди пристрій за моделлю, розміром і `TRAN=usb`. Наприклад, флешка 64 ГБ відображається як `/dev/sda` розміром близько `58.6G`.

**Далі в прикладах використовується `/dev/sda`. Заміни його на свій пристрій.** Команди з `/dev/sda` не можна виконувати, якщо це системний диск.

## 3. Запис Kali Live ISO (пропусти, якщо Kali Live уже записано)

Розмонтуй усі автоматично змонтовані розділи обраної флешки (лише ті, що показані в `lsblk`), наприклад:

```bash
sudo umount /dev/sda1
sudo umount /dev/sda2
```

Запиши завантажений образ, вказавши **точний шлях до ISO**:

```bash
sudo dd if=/home/USER/Downloads/kali-linux-VERSION-live-amd64.iso \
  of=/dev/sda bs=4M status=progress conv=fsync
sync
```

`USER` і `VERSION` — заповнювачі, заміни їх реальними значеннями. `of=` має вказувати **на пристрій**, не на розділ (`/dev/sda`, а не `/dev/sda1`).

Відключи і знову підключи флешку, потім перевір:

```bash
sudo parted /dev/sda unit MiB print
lsblk -f /dev/sda
```

Зазвичай після запису ISO є два розділи: `sda1` (Kali Live) і `sda2` (невеликий завантажувальний розділ), а решта місця вільна.

## 4. Створення третього розділу для Persistence

Якщо `lsblk` показує точки монтування у розділів флешки, розмонтуй їх:

```bash
sudo umount /dev/sda1
sudo umount /dev/sda2
```

Переконайся, що **вільне місце існує** і номера `3` ще немає:

```bash
sudo parted /dev/sda unit MiB print free
```

Створи розділ:

```bash
sudo fdisk /dev/sda
```

В інтерактивному `fdisk`:

1. `p` — подивитися поточні розділи.
2. `n` — додати розділ.
3. При запиті типу обери `p` (primary), якщо такий запит з’явився.
4. Номер розділу — `3`, якщо `fdisk` запитав його.
5. Початковий сектор — **Enter** (за замовчуванням).
6. Кінцевий сектор — **Enter** (усе доступне місце).
7. `p` — переконатися, що залишилися розділи 1 і 2 і додавсь розділ 3.
8. `w` — зберегти зміни.

На гібридному ISO `fdisk` може попередити про сигнатуру `iso9660`. **Не погоджуйся на окремий запит видалити сигнатуру вихідного ISO.** Якщо утиліта збирається стерти сигнатуру без можливості відмовитися, вийди через `q` і перевір розмітку перед продовженням.

Онови відомості про розділи і перевір результат:

```bash
sudo partprobe /dev/sda
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS /dev/sda
```

Очікуваний результат для флешки 64 ГБ: `sda1` близько 5–6 ГБ, `sda2` близько 4 МБ, `sda3` близько 53 ГБ. Якщо `sda3` не з’явився, перепідключи флешку; **не продовжуй**, доки не перевіриш пристрій.

## 5. Шифрування розділу LUKS2

Перевір, що `/dev/sda3` — потрібний розділ і він не змонтований:

```bash
lsblk -f /dev/sda
```

Якщо розділ змонтований, розмонтуй його. Потім виконай **руйнівну** операцію:

```bash
sudo cryptsetup --verbose --verify-passphrase luksFormat --type luks2 /dev/sda3
```

Підтверди введенням `YES` і двічі введи довгу унікальну парольну фразу. **Не втрачай пароль: без нього дані не відновити.**

Відкрий контейнер:

```bash
sudo cryptsetup luksOpen /dev/sda3 kali_persistence
```

Після введення пароля з’явиться `/dev/mapper/kali_persistence`.

## 6. Створення файлової системи та Persistence

**Форматуй лише відкритий LUKS-контейнер**, не вихідний `/dev/sda3`:

```bash
sudo mkfs.ext4 -L persistence /dev/mapper/kali_persistence
sudo mkdir -p /mnt/kali-persistence
sudo mount /dev/mapper/kali_persistence /mnt/kali-persistence

echo '/ union' | sudo tee /mnt/kali-persistence/persistence.conf
cat /mnt/kali-persistence/persistence.conf
```

Вміст `persistence.conf` має бути рівно:

```text
/ union
```

## 7. Безпечне завершення

```bash
sudo umount /mnt/kali-persistence
sudo cryptsetup luksClose kali_persistence
sync
sudo cryptsetup isLuks /dev/sda3 && echo 'LUKS OK'
```

Повідомлення `LUKS OK` підтверджує наявність LUKS-заголовка. Якщо хочеш витягти флешку:

```bash
sudo eject /dev/sda
```

## 8. Завантаження та перевірка

1. Підключи флешку до комп’ютера.
2. Обери USB у Boot Menu (залежить від моделі ПК: часто F12, F11, Esc).
3. Обери **Live USB Encrypted Persistence** (назва може трохи відрізнятися).
4. Введи LUKS-пароль.
5. У терміналі Kali створи тестовий файл:

```bash
echo 'Encrypted Persistence works' > ~/persistence-test.txt
sudo reboot
```

Знову завантаж **Encrypted Persistence**, введи пароль і перевір:

```bash
cat ~/persistence-test.txt
```

Якщо вміст зберігся, Persistence працює.

> Важливо: вибір звичайного `Live USB` не підключає зашифрований розділ автоматично. При кожному запуску для збереження змін обирай **Encrypted Persistence**.

## 9. Резервна копія LUKS-заголовка

Резервна копія заголовка важлива: пошкодження заголовка може зробити дані недоступними навіть за правильного пароля. Роби копію **на іншому захищеному накопичувачі**, а не на самій флешці. Не публікуй її: вона містить ключові слоти, важливі для безпеки контейнера.

Приклад (заміни шлях `/secure-backup` на каталог на іншому захищеному диску):

```bash
sudo cryptsetup luksHeaderBackup /dev/sda3 \
  --header-backup-file /secure-backup/kali-luks-header.img
sudo chmod 600 /secure-backup/kali-luks-header.img
```

Резервна копія заголовка **не замінює резервну копію файлів**. Відновлення старого заголовка після зміни пароля може відновити попередні ключові слоти; зберігай копію конфіденційно і оновлюй її після змін ключів.

## 10. Корисні перевірки

```bash
lsblk -f /dev/sda
sudo cryptsetup luksDump /dev/sda3
```

`luksDump` показує параметри шифрування, але не розшифровує дані.

### Якщо пароль не запитується або зміни не зберігаються

- Перевір, що обрано **Live USB Encrypted Persistence**, а не звичайний Live.
- Переконайся, що розділ має LUKS (`cryptsetup isLuks`) і файлова система **всередині контейнера** має мітку `persistence`.
- Перевір вміст `persistence.conf` (`/ union`).
- Переконайся, що під час запису ISO використовувався **Live ISO**, а не Installer.
- Не форматуй розділ повторно, якщо там уже є важливі дані.
